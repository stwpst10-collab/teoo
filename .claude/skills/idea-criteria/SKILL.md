# 팀원 아이템 발굴 기준 불러오기

요청: $ARGUMENTS

이 기준은 참고 자료다. 사용자가 부를 때만 쓴다(사용자 정정 2026-11-14: "반드시 이 기준으로 볼 필요는 없다").

## 원문 (매번 이 파일을 읽고 답한다)

`10-아이템탐색/근거/첨부/2026-11-14 팀원 새 아이템 리서치/팀원 아이디어 발전 기준과 프롬프트.md`

- 3절: 타깃 고객 발굴 프롬프트. **발굴 기준의 본체.**
- 1절: 아이템 정리 템플릿(충족 조건 6개, 입력·출력 양식)
- 2절: `business-idea-simulation` 스킬 전문(발전 11단계)
- 참고: 이 기준으로 걸러 나온 팀원의 타깃 후보 순위표와 채점표(120/140점)는 같은 폴더 `CJ 사내벤처 아이템 리서치 아카이브.md` 461~524줄에 있다.

파일이 없으면 저장소에서 `팀원 아이디어 발전 기준과 프롬프트`로 검색한다. 그래도 찾지 못하면 찾지 못했다고 알리고, 기억으로 기준을 지어내지 않는다.

## 어떻게 답하나

- **인자가 없을 때**: 3절의 발굴 기준을 번호 목록으로 보여 준다. 필요하면 1절의 충족 조건 6개를 덧붙인다. 원문 표현을 유지하고 해석을 덧붙이지 않는다.
- **아이디어를 줬을 때**: 발굴 기준 항목마다 그 아이디어가 맞는지(맞음 / 부족 / 확인 필요)와 이유 한 줄을 표로 쓴다. 근거가 없는 부분은 "확인 필요"로 둔다. 사용자가 요청하지 않았다면 리서치·장표 작업으로 넘어가지 않는다.
- 사용자가 "템플릿으로 정리해줘"라고 하면 1절의 출력 형식 0~5를 따른다. "시뮬레이션해줘"라고 하면 2절의 순서를 따른다.
