# 자료 전달 안내

자료가 저장소에 들어오는 길은 두 가지다. 어느 길로 왔든 도착 지점은 같다: **원본은 `30-근거/첨부`, 설명은 `30-근거` 출처 노트.**

| | 통로 A — 팀원이 직접 PR | 통로 B — 관리자에게 업로드 요청 |
|---|---|---|
| 누가 올리나 | 팀원이 작업 브랜치에서 | 관리자(사용자)가 대신 |
| 언제 쓰나 | 조사·해석까지 직접 쓴 경우 | 캡처·링크·파일만 있고 정리를 맡기는 경우 |
| 어디서 보나 | [PR 현황](PR-현황.md) → `요청/`·`검토/` | [자료 수집함](자료%20수집함.md) 표 |
| 기록되는 것 | PR 작성자·제출 버전 | 전달자·받은 날·요청 내용 |

## 팀원: 업로드를 부탁할 때 보낼 것

카톡 한 번에 아래를 같이 보내면 된다.

1. **원본 파일을 파일로 첨부.** 긴 글은 카톡 메시지 대신 txt·엑셀 파일로 보낸다(긴 메시지는 잘린다 — 2026-11-04 7사 분석 텍스트가 142/145에서 끊긴 사례).
2. **한 줄 요청:** "인식만" / "근거로 등록" / "○○ 리서치에 반영" 중 무엇인지.
3. **출처:** 게시물·기사 URL 또는 계정명, 찍은 날짜. 직접 표시(번호·밑줄·손글씨)를 했다면 그 의미.
4. **자기 해석이 있으면 따로 적기.** 원자료와 내 의견을 섞지 않는다.

## 관리자: 받은 자료 넣는 순서

1. **접수** — [자료 수집함](자료%20수집함.md)에 한 줄 추가(받은 날·전달자·자료·상태 `접수`).
2. **원본 보관** — `30-근거/첨부/<받은 날> <주제>/`에 원본을 그대로 복사하고 SHA-256을 대조한다. 파일명은 `<주제> 01 <내용>.jpg`처럼 한글로 바꾸되 원래 파일명은 출처 노트 표에 남긴다. 원본(바탕화면 등)은 지우지 않는다.
3. **출처 노트** — [근거 양식](../00-%EC%9A%B4%EC%98%81/%EC%96%91%EC%8B%9D/%EA%B7%BC%EA%B1%B0.md)으로 묶음 하나당 노트 하나. 본문에 **전체 판독문**을 둔다(나중에 검색으로 찾기 위해).
4. **구분 표시** — `source_kind`로 원자료 / 외부 2차 / 광고 / 커뮤니티 관측 / 팀원 분석을 나누고, 등급 A~D는 [[풀리포트 리서치 체계]]를 따른다. 해석은 "해석 메모"로 분리한다.
5. **수집함 갱신** — 상태·남은 일 기록. 보고서·지식 노트에 쓰면 `보고서반영`과 위치를 적는다.
6. **커밋** — 작업 브랜치에서 `원본 보관`과 `노트 반영`을 나눠 커밋하면 노트만 되돌리기 쉽다. 저장소가 PUBLIC이므로 push 전에 팀원 자료의 공개 가능 여부를 확인한다.

## 보고서에 쓸 때의 규칙

- `원문확인필요` 자료의 수치는 원문을 확인하기 전에는 보고서에 넣지 않는다.
- 광고(D)는 시장 근거로 쓰지 않고 사례로만 언급한다.
- 커뮤니티 회원 수·조회 수는 관측값이다. 고객 규모 추정치로 바꾸어 쓰지 않는다.
