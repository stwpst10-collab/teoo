# 이어받기 안내

저장소를 내려받은 팀원(또는 새 AI 세션)이 관리자의 작업 논리를 그대로 이어가기 위한 한 장짜리 안내다. 규칙 원문을 반복하지 않고 어디를 읽으면 되는지만 적는다.

## 2. 작업 논리: 자료가 판단이 되는 길

```text
자료 도착 ──▶ 30-근거 (원본 + 출처 노트, 판독문)          "무엇을 받았나"
               │
               ▼
          20-리서치 (질문 하나 = 파일 하나, 사실/주장/해석 구분)  "그래서 무엇을 알았나"
               │
               ▼
          10-지식 (주제당 한 노트의 현재 설명)              "지금 우리가 아는 것"
               │
               ▼
          40-결정 (팀이 고른 방향)  ·  50-검증 (질문·실험)
               │
               ▼
          80-산출물 (보고서·시뮬레이션·시안)               "밖에 보여주는 것"
```

- 아래 단계는 위 단계를 링크로 인용한다. 링크는 출처 표시이지 증명이 아니다.
- 새 자료가 기존 결정을 자동으로 바꾸지 않는다. 바꾸자는 제안은 근거·결정 ID와 함께 리서치에 적는다.
- 숫자는 값·단위·날짜·출처를 한 묶음으로. 원문 확인 전 수치는 보고서에 넣지 않는다.

## 3. 자료를 구분하는 세 가지 표시

| 표시 | 어디에 | 무엇을 가르나 |
|---|---|---|
| `source_kind` | 출처 노트 속성 | 원자료 / 외부 2차 / 광고 / 커뮤니티 관측 / 팀원 분석 |
| 등급 A~D | 출처 노트 `grade` | 보고서에 그대로 써도 되는 수준인지 ([[풀리포트 리서치 체계]]) |
| `delivered_by` / PR 작성자 | 출처 노트 / PR 카드 | 누가 언제 가져왔나 |

폴더는 주제·단계로 나누고 사람별로 나누지 않는다. 사람별로 보고 싶으면 수집함의 `전달` 열이나 PR 현황으로 거른다.

## 4. 내 작업을 올리는 법

- 직접 조사했다면: 통로 A — [팀원 PR 제출 안내](팀원%20PR%20제출%20안내.md)
- 캡처·파일만 있고 정리를 맡기려면: 통로 B — [자료 전달 안내](자료%20전달%20안내.md)
- 올리기 전 `python tools/validate.py` 실행.

## 5. 손대지 않는 것

- `30-근거/첨부` 원본은 수정·삭제하지 않는다(정정은 새 기록으로).
- `80-산출물/최종 보고서`는 편집장 세션만 고친다([[AI 세션 운영]]).
- 투자 온톨로지 등 외부 저장소의 자료를 이 저장소에 섞지 않는다.
