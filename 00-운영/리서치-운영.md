# 리서치 운영 방식

## 하나의 기준점

`venture`를 사업 지식의 기준 저장소로 사용한다. 원문은 근거, 읽고 정리한 내용은 주장·가설, 팀이 선택한 방향은 결정으로 구분한다. 발표자료는 이 기록을 참조해 만든 결과물로 취급한다.

원본자료·엑셀·산출물·작업 파일은 `90 작업자료`에 통합했다. 회의록과 팀원 이미지 10장은 `30-근거/첨부`에 보관한다. [[자료실|00 자료실]]을 파일 탐색의 시작점으로 사용한다. 앞으로 새 근거·파일도 이 vault 안에 저장하고 개념 노트에서 연결한다.

## 매번 같은 순서로 처리

1. **수집:** 새 자료는 `30-근거`에 출처·날짜·원본을 등록한다. 원본을 임의 수정하지 않는다.
2. **질문 연결:** [[리서치 질문 목록|리서치 질문 목록]]의 기존 질문을 찾고, 없을 때만 새 질문을 추가한다.
3. **판독:** 자료의 주장, 관측 결과, 추정을 구분한다. [리서치 양식](양식/리서치.md)에 출처 위치를 남긴다.
4. **판단:** 새 근거가 어떤 가정이나 결정에 영향을 주는지 적는다. 의견만으로 결정 상태를 바꾸지 않는다.
5. **갱신:** 현재 설명은 해당 개념 노트 한 곳에서 바꾸고, 과거 근거와 결론은 이력으로 보존한다.
6. **발표:** [[사업화 단계|사업화 단계]]에 맞춰 확인된 주장·근거·미확인 과제만 발표에 사용한다.

## 숫자는 조건까지 함께 관리

가격·원가는 값, 단위, 세금 포함 여부, 수량, 사양, 견적일, 출처를 한 묶음으로 기록한다. 회의 언급 원가를 기존 엑셀 입력값에 자동 대입하지 않는다. 린캔버스와 시뮬레이션의 차이는 [[리서치 질문 목록|리서치 질문 목록]] Q08에서 해소한다. 계산은 엑셀 모델에서 하고 노트는 입력값의 근거와 모델 위치를 관리한다.

## 바로 사용할 요청 예시

- “Q04의 기존 근거부터 확인하고, 견적에서 빠진 조건을 찾아줘.”
- “이 자료가 수동 목업 결정에 영향을 주는지 검토하고 출처와 함께 반영해줘.”
- “12월 발표에 쓸 수 있는 확인된 내용과 아직 주장뿐인 내용을 나눠줘.”

## 유지 방식

회의 뒤에는 결정·담당·기한의 변경만 점검한다. 리서치 전에 기존 질문과 근거를 검색한다. 일정 점검 때 미해결 질문을 우선순위별로 훑는다. 자동 동기화·공동편집·예약 작업은 아직 설정하지 않았다.


## Git 공동 작업

새 조사는 `20-리서치`, 새 근거는 `30-근거`, 통합된 설명은 `10-지식`, 결정은 `40-결정`에 둔다. 기존 작업자료는 이력으로 유지한다. [참여 절차](../CONTRIBUTING.md)와 [공동 브레인 운영안](공동-브레인.md)을 따른다.
