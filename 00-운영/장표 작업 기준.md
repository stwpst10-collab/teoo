# 장표 작업 기준 (그라운드 룰: 항상 팀 톤)

PPT 장표를 만들거나 고칠 때 매번 따르는 기준이다. 2026-11-28 사용자 지정: "장표 톤은 팀 톤으로 항상 맞춰 주는 걸 그라운드 룰로". 팀 장표 원본은 Figma `ROOMOVE_Drafts`(https://www.figma.com/deck/JdnnWZkrctuEPwmM0WfnS2/ROOMOVE_Drafts)다. 새 지적이 나오면 해당 절에 날짜와 함께 한 줄 추가한다.

## 1. 원칙
- 모든 장표는 팀 톤으로 만든다. 별도 "내 버전" 스타일은 사용자가 따로 요청할 때만 만든다(2026-11-28).
- 같은 주제 장표는 그 주제 PPT 파일 하나에 넣어 관리한다. 장표마다 단독 파일을 만들지 않는다(2026-11-28). 예: 산업·시장 장표 → `20-ROOMOVE/산출물/ROOMOVE 시장조사 팀 톤 2026-11-27 v1.pptx`.
- 사용자가 열어 둔 PPT는 닫지 않고, 열린 창에서 고치거나 장표를 넣은 뒤 저장한다(PowerPoint COM, `Slides.InsertFromFile`).

## 2. 장 구성(팀 장표와 같은 순서)
- 맨 위 작은 영어 라벨(13pt 굵게): Overview, Problem, Solution, Market, Competition, Expansion, Unit Economics, Risk, Next 등. 필요하면 "Expansion · 거주 중 관리"처럼 가운뎃점으로 세부 표시.
- 그 아래 제목(24~28pt 굵게): 결론 한 문장. 마침표 없이.
- 그 아래 부제 한 줄(14pt 굵게, 진회색): 제목을 받쳐 주는 문장, "~다."로 끝냄.
- 본문은 카드·차트·표로 짧게. 긴 문단 금지.
- 구분 장은 흰 바탕에 "1. 시장"처럼 번호와 이름만 크게(40pt).

## 3. 색과 모양
| 용도 | 값 |
|---|---|
| 바탕 | 흰색 FFFFFF |
| 글자 | 검정 111111, 보조 444444, 옅은 보조 8A8A8A |
| 일반 카드 | 회색 F2F2F2 (각진 사각형, 그림자·테두리 없음) |
| 강조 카드 | 검정 161616 + 흰 글자 |
| 강조색 | 파랑-보라 3B37E8, 단계 표현은 연보라→파랑 D9D7FF·B9B6FF·8E8AFF·5F5BF7·3B37E8 |
| 핵심 숫자 | 주황-빨강 D4380D (검정 카드 위에서는 FF8A65) |
| 연한 강조 바탕 | E9E8FF·EEEDFF |
| 성장/정체 차트 | 성장은 강조색, 정체·감소는 회색 BDBDBD·9E9E9E |
- 단계는 화살표 띠(연보라→파랑 셰브런), 흐름은 → 화살표, 번호는 파란 원 안 흰 숫자.
- 색 띠·옆줄 장식, 제목 밑줄은 쓰지 않는다.

## 4. 글
- 문장은 "~다."로 끝낸다(팀 장표 말투). 보고서의 개조식 명사형과 다르다.
- 외래어·약어는 풀어 쓴다(보고서 워드 작업 기준 2절과 같음). 숫자는 보고서·시뮬레이션의 검증 값만 쓰고, 추정은 "당사 추정·당사 판단"으로 밝힌다.
- 금액 칸 이름은 "수익원"(2026-11-27).
- 맨 아래 가운데에 「자료: …」 한 줄(8.5~9pt, 옅은 회색). 추정·잠정·역산은 여기서 밝힌다.

## 5. 글꼴·크기
- 맑은 고딕(팀 Figma 글꼴이 이 PC에 없음). 본문 10~14pt, 카드 제목 13~18pt, 큰 숫자 24~46pt.
- 한글이 단어 중간에서 잘리지 않게 생성 뒤 `20-ROOMOVE/tools/deck_korean_wrap.py`(lang=ko-KR, eaLnBrk=0)를 돌린다.

## 6. 만드는 방법
- 스크립트: `20-ROOMOVE/tools/build_slide_*.js`, `build_slides_timeseries.js`, `build_deck_team.js`(pptxgenjs). 새 장표도 같은 헬퍼(T·rect·pill)와 색 값을 쓴다.
- 만든 뒤 PowerPoint로 PNG를 뽑아 넘침·겹침을 눈으로 확인하고, 주제 파일에 넣은 뒤 main에 올린다.
