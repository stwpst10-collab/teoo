# 풀리포트 리서치 체계

12월 지주사 발표를 **애널리스트 산업분석 + 기업분석 풀리포트 수준**으로 만들기 위한 리서치 바탕이다. 모든 조사는 결국 [[최종 보고서 설계|최종 보고서 설계]]의 어느 장을 채우는지로 연결한다. 기존 [[리서치-운영|리서치 운영 방식]]과 [[온톨로지-규칙|온톨로지 규칙]]을 그대로 따르고, 이 문서는 보고서용 층만 더한다.

## 구조: 위에서 아래로

```
최종 보고서 설계 (80-산출물, OUT-004)      ← 장별 핵심 메시지와 근거 충족 상태
   └ 장(1~10) ── 필요한 질문 Q (50-검증/리서치 질문 목록)
                   └ 리서치 (20-리서치, 질문 하나당 파일)
                        ├ 근거 (30-근거, 원문 보존)
                        ├ 수치 → 시장 수치 대장 (N 번호)
                        └ 반영 → 지식 노트 (10-지식, 주제당 하나)
                                  ├ 사업·비전  VIS-001
                                  ├ 시장 세그먼트 SEG / 수요 동인 DRV   (10-지식/시장)
                                  ├ 비교기업 CMP                       (10-지식/비교기업)
                                  └ 고객·제품·사업모델 (기존)
   결정 (40-결정) ← 팀이 고른 방향만. 리서치가 자동으로 바꾸지 않음
```

## 새 노트 종류

| type | 폴더 | 한 노트에 담는 것 | 양식 |
|---|---|---|---|
| segment | 10-지식/시장 | 시장 하나의 정의·경계·규모·플레이어 | [세그먼트](양식/세그먼트.md) |
| driver | 10-지식/시장 | "왜 수요가 구조적으로 느는가" 주장 하나와 근거 | [수요동인](양식/수요동인.md) |
| company | 10-지식/비교기업 | 비교 기업 하나의 사실·확장 경로·시사점 | [비교기업](양식/비교기업.md) |
| metric-ledger | 10-지식/시장 | 보고서의 모든 숫자 | [[시장 수치 대장]] |
| output(report) | 80-산출물/최종 보고서 | 장 구성·메시지·근거 상태 | [[최종 보고서 설계]] |

기존 경쟁 대안([[기존 대안]], [[오비라]])은 제품 폴더에 그대로 둔다. 비교기업 노트는 "우리가 배우려는 기업", 대안 노트는 "고객이 지금 대신 쓰는 것"이다.

## 근거 등급

| 등급 | 해당 | 보고서 사용 |
|---|---|---|
| A | 공시(DART·SEC), 정부 통계(KOSIS·심평원), 규제 문서(식약처·FDA), 논문 원문, 직접 실측·설문 원자료 | 핵심 수치·주장에 그대로 사용 |
| B | 증권사·리서치 리포트, 조사기관 보고서 원문, 주요 언론의 원문 인용 | 출처 명시 후 사용 |
| C | 업체 주장, 판매용 리포트 요약, 검색 요약, AI 답변 | "주장/추정"으로 표시. 핵심 결론의 단독 근거 금지 |
| D | 팀 가설, 내부 추정, 회의 발언 | 가정으로 표시하고 시뮬레이션 입력값과 연결 |

AI(GPT·Claude) 답변은 출처를 대지 않으면 C다. 답변이 인용한 원문을 직접 확인하면 그 원문의 등급을 준다.

## 숫자 규칙

1. 보고서에 들어갈 숫자는 먼저 [[시장 수치 대장]]에 N 번호로 등록한다.
2. 값·단위·통화·기준연도·정의·출처·확인일·등급을 한 줄에 같이 쓴다.
3. 같은 지표의 다른 추정치는 지우지 않고 나란히 둔다. 보고서에는 범위나 채택 이유를 쓴다.
4. 세그먼트끼리 더할 때 같은 고객의 중복을 확인한다. 구매자 수 확장과 고객당 지출 확장을 구분한다.
5. 계산은 [[시뮬레이션 모델링]] 엑셀에서 하고, 노트에는 입력값의 N 번호를 적는다.

## 한 번의 딥리서치 사이클

1. **장 고르기:** [[최종 보고서 설계]]에서 근거 상태가 "미착수"인 장과 Q를 고른다.
2. **기존 검색:** 같은 Q의 리서치·근거·대장 항목을 먼저 찾는다.
3. **수집:** 원문을 `30-근거`에 등록한다(공개 저장소이므로 재배포 불가 원문은 링크와 요약만).
4. **판독:** `20-리서치/<주제>.md`에 사실·주장·해석·반대 근거를 나눠 쓴다.
5. **반영:** 숫자는 대장, 설명은 해당 SEG/DRV/CMP/VIS 노트 한 곳에 갱신한다.
6. **장 상태 갱신:** [[최종 보고서 설계]]의 근거 상태와 남은 공백을 고친다.
7. **검사:** `python tools/validate.py`.

## 딥리서치 요청 예시 (Claude·Codex에 그대로 사용)

- "최종 보고서 2장을 채우려 해. Q17 기준으로 국내 15~49세 여성 인구와 월경 장애 진료 인원을 KOSIS·심평원 원문에서 찾아 수치 대장에 등록하고 [[생리 전후 셀프케어 시장]]을 갱신해줘."
- "CMP-001 에이피알을 비교기업 양식대로 채워줘. DART 최근 사업보고서 기준 매출 구성, 디바이스 라인업, 해외 채널을 출처와 함께."
- "Q24: Hyperice·Beurer EM50·Embr·Sea-Band 공식 자료를 확인해서 GPT 주장(C)을 원문 등급으로 바꾸거나 반박해줘."
- "3장 수요 동인 DRV-001~005 중 근거가 C 이하인 것을 A/B로 올릴 수 있는 원문을 찾아줘."

## 완료 기준

보고서의 각 장은 (1) 핵심 메시지 한 문장, (2) 그 문장을 받치는 A/B 근거 2개 이상, (3) 반대 근거나 한계, (4) 남은 공백이 적혀 있을 때 "근거 확보"로 표시한다. 링크 검사 통과는 사실 검증이 아니다.
