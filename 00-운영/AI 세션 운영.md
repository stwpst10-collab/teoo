# AI 세션 운영

여러 Claude/Codex 창을 동시에 쓸 때 서로 덮어쓰거나 맥락이 꼬이지 않도록 하는 규칙이다. 기존 [[리서치-운영|리서치 운영 방식]]과 [[풀리포트 리서치 체계|풀리포트 리서치 체계]]를 그대로 따르고, 이 문서는 **세션 역할과 인계 방법**만 더한다. 현재 누가 무엇을 하는지는 [[작업 현황판|작업 현황판]]에 적는다.

## 원칙: 쓰는 세션은 파일 영역마다 하나

세션은 주제가 아니라 **쓰는 위치**로 나눈다. 읽기는 어느 세션이든 자유롭지만, 같은 파일을 두 세션이 동시에 수정하지 않는다.

| 역할 | 동시 개수 | 쓰는 위치 | 하지 않는 것 |
|---|---|---|---|
| **리서치** | 여러 개 가능 | `20-리서치/` 새 파일, `30-근거/` 새 근거 | 보고서·지식 노트·결정 수정 |
| **편집장** (최종 보고서) | **1개** | `80-산출물/최종 보고서/`, [[최종 보고서 설계]] | 새 리서치를 직접 수행(필요하면 리서치 세션에 요청) |
| **온톨로지 구축 (FDE)** — 구 '정리' 역할 포함 | 1개 | `00-운영/온톨로지-규칙.md`, `00-운영/양식/제조 기록.md`, `60-제조/`, `tools/ontology/`, `10-지식/`, `40-결정/`, `50-검증/`, Canvas | 보고서 수정, 새 리서치, 무엇을 만들지 결정(제품 기획·설계 담당), 앱 코드(IT·앱 개발 담당) |

- **온톨로지 구축 (FDE)** 은 사이드바의 '온톨로지 구축' 하위가 맡는다(2026-11-06 신설). FDE(현장 배치형 엔지니어) 개발자로서 제조 현장의 기록(시제품·업체·견적·부품·시험·이슈)을 온톨로지 구조로 설계하고, 수집·검사·연결 도구를 만든다. 목적은 제조 효율이다. 기존 '정리' 역할(10-지식·40-결정·50-검증·Canvas 정리)도 이 하위가 맡아 온톨로지 담당을 하나로 둔다.
- 제품 기획·설계 하위는 "무엇을 만들지"를 정하고 `80-산출물` 시안과 결정 제안을 쓴다. 온톨로지 구축 하위는 "만든 과정과 결과"를 `60-제조`에 구조화해 다음 버전·다음 제품에서 재사용하게 한다.

- 동시에 여는 창은 **2~3개**(편집장 1 + 리서치 1~2)를 기본으로 한다.
- 창 이름을 역할로 붙인다. 예: `편집장`, `리서치-홈케어`, `리서치-APR 그림`.
- 편집장 세션은 필요하면 별도 워크트리(`../venture-report`, 브랜치 `report/…`)에서 작업한다. 이 경우 Obsidian에는 병합 전까지 보이지 않는다.
- **커밋·푸시는 항상 main까지 반영한다 (2026-11-07 사용자 지시).** 지금은 사용자 혼자 로컬에서 올리므로, 작업 브랜치에 push한 뒤 바로 main에 병합해 main도 push한다. docx·pdf·xlsx·html 산출물도 빠짐없이 커밋한다. 팀원 PR 규칙(`05-협업/팀원 PR 제출 안내.md`)은 팀원 제출용이며 사용자 본인 작업에는 이 줄이 우선한다.

## Orca 상위·하위 구조 (2026-11-04)

- **상위 = 최종 편집자.** Orca의 `사내벤처` 상위 탭("최종 보고서용 워크트리", 세션 이름 claude-e3)이 작업을 배분하고, 결과를 검토하고, **커밋을 승인·실행하는 유일한 곳**이다.
- **하위 = 작업 담당.** 사용자가 Orca에서 하위 워크스페이스를 만든다(예: `경쟁사`). 상위는 `orca terminal send`로 하위 Claude 탭에 지시하고 `orca terminal read`로 진행을 확인한다. 사용자는 필요하면 하위 탭에 들어가 직접 대화한다.
- **하위는 커밋하지 않는다.** 파일 저장과 `python tools/validate.py` 확인까지만 하고, SendMessage로 claude-e3에게 `커밋 요청: <파일 경로 목록> / 요약`을 보낸다.
- 상위는 요청받은 파일을 읽고 채택·보류·수정 요청을 판단한 뒤 커밋한다. 판단 결과는 [[작업 현황판]]의 "편집장 대기"·"반영 완료" 표에 남긴다.
- 하위 담당 영역: `경쟁사` = 경쟁사·비교 기업 조사 전담(다른 탭에서 경쟁사 조사를 하지 않는다).
- Orca에서 `사내벤처`는 일반 폴더로 등록돼 하위도 같은 폴더를 공유한다. 하위끼리 같은 파일을 쓰지 않도록 상위가 작업 범위를 나눠 보낸다.

## 인계는 대화가 아니라 파일로

세션끼리 내용을 복사·붙여넣기로 옮기지 않는다. 다른 세션은 이 창에서 나눈 대화를 모른다.

1. **리서치 세션 종료 시** 결과를 [리서치 양식](양식/리서치.md)으로 `20-리서치/`에 저장하고, 양식 끝에 아래 절을 추가한다.

   ```markdown
   ## 보고서 반영 포인트

   | 보고서 장 | 반영할 내용 (한 줄) | 근거 위치 | 확인 상태 |
   |---|---|---|---|
   | 예: 4장 경쟁 | 경쟁사 7사 중 소모품 반복구매 구조는 2사 | [[근거 노트]] 표 2 | 확인 / 업체 주장 / 미확인 |
   ```

2. 그다음 [[작업 현황판|작업 현황판]]의 "편집장 대기" 표에 파일 링크를 한 줄 추가하고 세션을 닫는다.
3. **편집장 세션 시작 시** 작업 현황판의 대기 목록만 읽고 반영 여부를 판단한다. 반영한 항목은 보고서 버전과 함께 "반영 완료"로 옮긴다.

## 한 세션에는 목표 하나

- 시작할 때 끝나는 조건을 정한다. 예: "v10에서 4장 경쟁 구도만 수정", "홈케어 디바이스 가격대 원문 3건 확인".
- 목표를 끝내면 결과를 파일로 남기고 새 세션을 연다. 대화가 길어지면 앞부분이 요약되면서 세부 조건이 사라진다.
- 여러 대상을 병렬로 조사할 때는 창을 늘리지 말고 한 세션에서 "각각 조사해 결과를 합쳐줘"라고 요청한다(서브에이전트 활용).

## 작성과 검증은 다른 세션에서

- 보고서 새 버전을 만든 세션이 스스로 최종 검증하지 않는다.
- 새 세션에서 "v○의 수치·출처를 30-근거·20-리서치 원문과 대조해줘"를 별도로 실행하고, 불일치는 작업 현황판의 "검증 지적"에 남긴다.
- `python tools/validate.py` 통과는 링크·속성 검사일 뿐 사실 검증이 아니다.

## 커밋 단위

- 커밋은 상위(최종 편집자)만 한다. 하위는 커밋 요청을 보낸다(위 "Orca 상위·하위 구조").
- 상위는 요청 단위로, 요청받은 파일만 커밋한다. 다른 세션의 미커밋 파일을 함께 올리지 않는다.
- 커밋 전 `git status --short`로 다른 세션의 변경이 섞였는지 확인한다([AGENTS.md](../AGENTS.md) 2항).
