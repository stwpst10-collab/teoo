# 파일명과 메타데이터

파일명은 사람이 내용을 바로 이해하도록 한글 주제를 먼저 쓴다. `ALT-002`, `SRC-…`, `OUT-001` 같은 내부 ID는 파일명에 붙이지 않고 문서 속성의 `id`에만 보관한다. 그래프에 표시되는 이름은 실제 파일명이므로 별칭만 추가하는 방식으로 해결하지 않는다.

| 종류 | 이름 예시 | 구분 방법 |
|---|---|---|
| 사업·제품 지식 | `그날의 류.md`, `발목형 웰니스 디바이스.md`, `오비라.md` | 주제당 하나 |
| 리서치 | `오비라 커뮤니티 수요 검증.md` | 같은 주제의 별도 조사에는 날짜·작성자 추가 |
| 출처 노트 | `경쟁사 제품 분석 원본.md`, `개발 회의록 2026-10-27.md` | 조사 해석과 원본을 구분 |
| 결정 | `수동 시연 목업 결정.md` | 결정이라는 역할 표시 |
| 검증 | `100일 검증 계획.md`, `리서치 질문 목록.md` | 계획·관측 결과 구분 |
| 산출물 설명 | `시뮬레이션 모델링.md`, `프로토타입 시안.md` | 유형을 한글로 표시 |
| 실제 산출물 | `시뮬레이션 모델링 2026-10-29 v2.xlsx` | 유형·내용·날짜·버전 |
| 원본 이미지 | `팀원 프로토타입 제안 슬라이드 01.png` | 내용·순서, 출처 노트에서 날짜 관리 |

공백을 사용할 수 있다. 같은 이름의 노트를 여러 폴더에 만들지 않는다. 제목이 겹치면 대상·날짜·작성자를 덧붙이고 `최종`, `수정본2` 같은 모호한 이름을 피한다. 원본 파일 이름 변경 시 내용은 보존하고 이전 이름·새 이름·SHA-256을 기록한다. 이번 이력은 [한글 파일명 변경 기록](한글파일명변경-20261029.json)에 있다.

## 내부 식별과 속성

지식·리서치·출처 노트·결정·검증 문서는 `id`, `type`, `status`, `project`를 유지한다. ID는 중복 없이 고정하며 이름 변경으로 바꾸지 않는다. 파일명과 ID가 일치할 필요는 없다. 기존 ID의 영어 접두어는 내부 식별 용도로만 사용한다.

리서치는 `author`, `created`, `question`, `review`, `source_status`도 기록한다. `review`는 pending/reviewed, `source_status`는 primary/secondary/mixed/unverified다. 질문 번호와 작성자 핸들은 속성에서 관리한다. 검토자·승인일을 만들어내지 않는다.

`status`는 가설·검증 중·판단유보 같은 내용의 상태, `review`는 동료 검토 여부다. 문서 통합은 효능·수익성 입증이나 사양 확정과 다르다.

## 산출물의 분류와 연결

사용자용 산출물은 `80-산출물`에 보관한다. 설명 노트는 `type: output`, `output_kind`, `id`, `status`, `project`, `updated`를 갖는다.

| 표시 유형 | 내부 output_kind | 연결할 내용 |
|---|---|---|
| 시뮬레이션 모델링 | simulation-model | 입력 가정·반영 조사·검증 범위·현재 파일 |
| 프로토타입 시안·제안 | prototype-concept | 대상 제품·참조 결정·제안 상태·이미지와 HTML |

동일 산출물의 PNG·HTML 등은 같은 설명 노트에서 연결한다. 새로운 용도의 제안은 별도 노트와 ID를 사용한다. 기존 이력 자료는 현재 파일과 구별해 보존한다.

## 링크와 검증

위키링크는 현재 한글 파일명을 사용한다. 일반 Markdown 링크의 공백은 `%20`으로 표현하거나 경로를 `<…>`로 감싼다. 이름을 바꾸면 문서·Canvas·HTML의 참조도 함께 갱신한다. `python tools/validate.py`로 ID 중복·필수 속성·링크를 검사한다.

검증 스크린샷은 `.local` 임시 공간에서 만들고 확인 후 삭제한다. 사업 근거 원본과 실제 프로토타입 시안은 삭제 대상이 아니다.

새 문서는 [리서치](양식/리서치.md), [근거](양식/근거.md), [결정](양식/결정.md) 양식을 사용한다.
