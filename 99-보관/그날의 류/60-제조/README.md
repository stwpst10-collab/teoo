# 60-제조

검증(50)·결정(40)을 거친 제품을 **실제로 만들어 보는 과정**의 기록이다. 리서치도, 결정도, 확정 지식도 아닌 **운영 기록**을 둔다. 목적은 제조 효율이다. 같은 시행착오를 다음 버전·다음 제품에서 반복하지 않도록, 시제품·업체·견적·부품·시험·문제를 서로 연결해 남긴다.

## 지식 흐름에서의 위치

아이디어(15) → 리서치(20) → 근거(30) → 검증(50) → 결정(40) → **제조(60)** → 확정 지식(10) / 산출물(80)

- 원본(견적서·시험성적서 PDF, 사진)은 `30-근거/첨부/`에 두고, 여기에는 구조화한 기록과 링크만 둔다.
- 업체 선정·소재 변경처럼 팀이 채택하는 판단은 `40-결정/`에 결정 문서로 쓰고 여기서 링크한다.
- 기록에서 뽑은 교훈과 측정값(개선 주기, 반복된 시행착오 건수)은 [[제조 역량 학습 기록]](CAP-001)에 요약한다.
- "무엇을 만들지"는 제품 기획·설계 하위가 정한다. 이 폴더는 "만든 과정과 결과"를 남긴다.

## 하위 폴더

| 폴더 | type | ID | 한 노트에 담는 것 |
|---|---|---|---|
| `시제품/` | prototype | PRT | 시제품 버전 하나: 무엇을, 왜 바꿨나, 결과 |
| `업체/` | supplier | SUP | OEM·부품사 하나: 역할, 연락 이력, 합의 상태 |
| `견적/` | quote | QUO | 견적 비교 하나: 같은 사양의 업체별 단가·수량·조건 |
| `부품·BOM/` | part | PART | 부품 또는 BOM 한 판: 구성, 원가, 공급 업체 |
| `시험/` | test | TST | 시험 하나: 대상 시제품, 방법, 결과, 판단 |
| `이슈/` | issue | ISS | 문제 하나: 현상 → 원인 → 조치 → 재발 여부 |

새 기록은 [제조 기록 양식](<../00-운영/양식/제조 기록.md>)을 쓴다. 항목 종류와 관계 정의는 [[온톨로지-규칙]]의 "2026-11-06 추가: 제조 항목"을 따른다.

## 기록 원칙

- 미팅·견적·시험이 끝나면 24시간 안에 기록한다.
- 실패한 시도도 지우지 않는다. 실패 원인이 다음 제품의 자산이다.
- 업체 발언, 견적 수치, 실측 결과, 팀 추정을 섞지 않는다. 각 줄에 성격을 표시한다.
- 기록이 쌓였다는 것은 제조 역량의 증거이지 효능·수익성의 증거가 아니다.
