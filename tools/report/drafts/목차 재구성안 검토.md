## 2. 중복 정리(같은 표가 세 번 나오지 않게)

- 확장 단계는 다음 네 곳에 나옴:
  - 1.3 확장 지도
  - 2.5 확장 경로
  - 3.3 조건부 후속 후보
  - 6.2 실패 원인별 전환 경로
- 역할을 나눔:
  - 1.3은 그림(주장).
  - 2.5는 근거·규모·반대 근거.
  - 3.3은 제품 순서.
  - 6.2는 실패 시 경로.
  - 표는 2.5에만 두고 나머지는 참조로.
- 웨어러블은 2.5 갈래(시장)와 3.5 웨어러블 연동(제품·데이터)에 나옴. 3.5 쪽은 H1~H3 단계표에 행으로만 붙이기를 권함.
- 기록 축적은 1.5와 6.3에 나옴. 1.5에는 주장 1문단과 6.3 참조만 둠.

## 4. 기술 변경 메모(v10.9 빌드용, 지금 미적용)

1. `build_fullreport.py`
   - TOC 필드를 `\o "1-2"` → `\o "1-3"`으로 바꿈.
   - `h2()`는 이미 있고 장마다 번호를 초기화함(`H['h2']=0`).
   - 목차가 길어지므로 목차 쪽 수를 빌드 후 확인함. Heading 3 항목은 수십 개라 2~3쪽 예상(추정).
2. `s1`의 "■ " 접두어가 목차에 그대로 나옴. TOC에 ■가 보이지 않게 하려면 다음 중 하나를 고름:
   - ■를 문단 번호·글머리 기호 서식으로 바꿈.
   - TOC를 `\o "1-2"` + `\t "TOC 3용 스타일,3"` 같은 별도 스타일로 만듦.
   - ■를 받아들임.
3. 1장 `overview()`가 h1 직후에 `s1('핵심 지표')`를 넣음. 1.1보다 앞에 오는 Heading 3라 목차에서 장 바로 아래에 번호 없이 붙음. "핵심 지표"를 h2로 둘지(1.0이 아니라 1.1이 되어 번호가 하나씩 밀림), 문단 서식으로 바꿔 목차에서 뺄지 정해야 함. 후자를 권함.
4. `build_html.py`는 현재 `h2`를 `s1`로 매핑함(113~114행). 웹 목차와 번호도 3단계로 바꿔야 docx와 같아짐. `test_build_html.py` 기대값도 갱신함.
5. "v8 대비 변경 요약"·"검토 중 의문사항" 쪽은 제목이 일반 문단이라 목차에 들어가지 않음. 현행 유지를 권함.
